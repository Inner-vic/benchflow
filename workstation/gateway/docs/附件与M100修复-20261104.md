# 附件接收与 M100 编译修复

## 已部署

- 工作站 `bench_gateway/feishu_files.py` 使用 8 MiB Range 分片、逐块写磁盘、完整 SHA256；校验 Content-Range、长度、总大小及返回的 ETag。瞬时网络错误只重试当前分片，回退未完成字节，不重复登记文件。
- 接口上限仍由 `attachment_max_bytes` 控制，缺省 128 MiB。本轮不扩大软件包、数据集的传输用途。
- `package_assembly.py` 对历史收据只应用本人 `storage_mappings` 中已登记的迁移映射。远端仍核对当前文件、源包和配方哈希。历史收据不改写，不按文件名或版本标签放宽兼容检查。
- 无 M100、方式为 `build_if_missing` 时，材料通过前置检查后调用工作站编译。提供成品时走成品核验。修复没有改变确认、FIFO、台架锁或冻结输入规则。

## 官方限制

[获取消息中的资源文件](https://open.feishu.cn/document/server-docs/im-v1/message/get-2) 的当前说明允许 `type=file` 使用 Range 下载 100 MB 及以上资源，每次分片不超过 32 MB。小于 100 MB 可普通下载。流式写入节省内存，Range 解决分片协议限制，两者需区分。

机器人文件上传是另一接口，其限制不能套用到用户从聊天客户端上传的附件。APP 和数据集仍通过链接或工作站/开发空间路径提供。

## 真实验证

- 同一份原生聊天 M100 附件为 104,331,960 字节。13 片下载耗时 28.721 秒，约 3.464 MiB/s。SHA256 `54b4c81128b4be576166efd4a6516559e208c8f5b2419a12e6b0a835ccd2ecf2`。
- 原消息通过正常工作站附件接收路径补接，状态 ASSOCIATED，绑定原本人任务，材料从 revision 2 更新为 3，M100 方式 provided，等待重新确认；未创建执行 Job。
- 缺省 M100 分支单独实际调用编译器，2737 构建成功，产物 101,756,152 字节，SHA256 `ea5f9cabd3e7ef0ff78cc9d1bbe6ac70bc0cb91e54a3f606ab594a87ea526a28`。该验证只生成本人工作站资产，没有刷包或回灌。
- 15 项新增分片/迁移映射测试通过，18 项已有配方/M100 构建与准备测试通过。
- 部署前备份两个原文件、一致性数据库快照与维护状态。部署后原任务、附件、确认、自动任务及 Job 不变，桥接和 worker 就绪，随后补接已明确授权的原附件。
