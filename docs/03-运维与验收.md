## 各设备检查

| 项 | 检查方法 | 能证明什么 |
|---|---|---|
| Windows CC | desktop-frontend/status、新鲜连接租约、唯一CC进程 | 实际连接端就绪；不是台架运行证据 |
| Windows解析 | 独立计划任务和parser连接；有限结构化解析 | 复杂意图/YAML能力；不要求普通消息都调模型 |
| Linux监督器 | runtime/service/status、进程及两子进程ready | 当前存活；systemd托管另查，不能据ready推断重启恢复 |
| SSH/台架 | 固定SSH探测及Runner状态 | 区分网络、认证、指纹和锁；不能把所有失败叫物理断连 |
| Runner | 正式CLI及候选扩展、原子JSON锁 | 最终互斥；不改用flock或touch该锁 |
| 云端 | 平台实例状态、当前generation心跳、profile/挂载 | 接收端可用；不是主认证永久有效的证明 |

源码合并与部署分开。使用本次文件清单及部署前摘要检查；排空后原子替换经测文件，按需要恢复既有托管入口，核对会话、资产、确认、任务、原Run及新鲜心跳。不得恢复旧数据库覆盖维护期间新消息。

## 故障定位顺序

| 现象 | 先查 | 后续 |
|---|---|---|
| 附件在聊天有、卡片没有 | 原消息、desktop引用收据、task_attachments及批次状态 | 原消息核验后补接；日志不足不猜大小或超限 |
| 缺M100但未编译 | 本轮wants_build、APP/传感器/YAML前置问题、配方及编译记录 | 区分尚未开始、失败、结果未知，不无限重编 |
| 长时间材料检查 | 当前真实phase与timings | 下载/编译可长；数据常规不逐帧；当前准备全局串行 |
| 一直排队 | 队首、当前使用者、availability、Runner锁 | 正常忙等待；损坏/未知结果待核验 |
| 回放100%未完成 | 正式服务恢复、产品收据、结果目录 | 不提前成功，不重复场景 |
| 评测很慢/失败 | 实例心跳、上传、任务GT匹配、原生评测和TXT阶段 | 不搬整份GT、不重放台架；未知结果续收 |
| 卡片或TXT没送达 | durable outbox、任务卡状态、发送错误 | 只重试通知；必要时从工作站已有报告交付 |
