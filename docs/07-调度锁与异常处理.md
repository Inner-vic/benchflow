# 台架评测：调度、锁与异常处理复核

2026-11-05。本次以台架评测主链路复核；其他项目仅涉及共享入口故障隔离和同一台架的资源边界，不合并业务材料、评测器或报告。

## 为什么既有队列又有锁

| 机制 | 解决的问题 | 删除后的问题 |
|---|---|---|
| 本人会话及材料确认 | 确定谁提交了哪份材料，防止上传到一半就执行 | 串行执行仍可能用错人、错版本或未齐材料 |
| 全局硬件FIFO | 多人有序等待，同一Job只领取一次 | 同时确认可能同时派发，不能保证公平等待 |
| 单硬件worker进程锁 | 防止第二个调度器领取另一硬件任务 | 两个服务实例可能同时控制台架 |
| Runner原子JSON台架锁 | 协调安装器、Runner及其他直接调用者，记录执行所有权 | FIFO不能约束绕过本入口的调用者；检查空闲到真正执行之间也存在竞争 |
| 冻结输入及执行收据 | 防止重启、重复回调或通知重试重新操作台架 | 仅凭“现在空闲”无法判断上次是否已经执行过 |

因此保留现有JSON锁，不新增第二套板端锁。它是小型所有权记录，不是永久监控服务。原Runner使用独占创建和0600权限；不能用flock、touch或重定向占同一路径。

PID、时间和心跳只供诊断，不能证明硬件已经恢复。锁有效且属于其他执行时等待；空文件、内容损坏、身份不符或执行结果未知时停止派发并待核验。禁止按超时或PID消失自动删除。释放依据来自原执行的恢复/未激活证明；锁文件本身不代替恢复证据。

## 沿主链路追问

| 环节 | 为什么保留 | 本次核查与处理 |
|---|---|---|
| 消息、附件、转发构建卡 | 文件接收成功和材料已登记是不同事实 | 本人、会话、任务版本及附件批次校验保留；普通PCM消息不再先加载另一业务插件 |
| 点击确认执行 | 用户可能还在补第二份SO或修改YAML | 只认真实当前卡片确认，重复回调去重；不替用户确认 |
| APP/SO/YAML准备 | 新包不一定能沿用旧接口，旧成功不代表板上当前版本 | 相机/雷达可沿用本人候选并继续检查；新APP清旧M100；YAML为任务副本 |
| M100自动编译 | 减少大文件上传，且必须与APP及锁定依赖一致 | 前置APP/依赖失败时标明尚未编译，不再叠加“未提供成品”假错误；真实缺配方/编译失败仍停止 |
| 数据源准备 | 场景范围和输入路径必须确定，避免重复搬运大文件 | 场景级检查及完整场景缓存复用保留；日常不逐帧扫描；云端只下载original，GT不下载 |
| 适配器绑定 | 记录本次软件、数据、配置和执行代码身份 | 程序升级后，仅对未提交且已过期的准备重新检查/绑定；不修改已提交Job |
| 硬件领取、刷包、预检 | 当前板上可能已被他人换包；静态检查不能代替启动 | FIFO和原JSON锁都保留；预检失败不进入正式全量 |
| 正式回放、恢复、收集 | 回放100%不代表服务已恢复或结果已落盘 | 必须取得正式执行与恢复收据后交付；正式阶段遇忙不重复已完成预检 |
| 云端评测 | 需要本任务GT关联，不能套用其他数据集 | 预测上传独立输出位置；缺GT明确失败/部分完成，不修改指标或阈值 |
| 原卡与附件交付 | 飞书网络失败不应造成再次刷包、回放或评测 | 通知单独重试；只交付原任务结果，不重新执行硬件 |

## 失败和异常的处理边界

| 发现时点/证据 | 状态和动作 | 是否重试台架 |
|---|---|---|
| 未确认、附件接收中或材料变化 | 保留材料并更新卡片，等待当前版本确认 | 否 |
| APP下载、静态兼容、YAML或编译明确失败 | 提示真实缺项；修复后重新检查 | 否 |
| 尚未派发，连接不可达 | 保持就绪/等待，在原卡提示连接异常 | 无新派发；恢复后仍经原门禁 |
| 尚未派发，有效的其他执行占用 | 同一Job回到队列，等待资源 | 轮到后派发，不能把正常忙直接判待核验 |
| 台架锁损坏或身份异常 | 保留原锁和证据，停止硬件派发，管理员核验 | 否；不自动清锁 |
| 可证明本次尚未执行的拒绝 | 明确失败，材料保留 | 不自动循环重试 |
| 预检失败且恢复通过、无锁/链接残留 | 本次失败，不进入全量 | 否 |
| 预检失败且恢复证据不足 | 待核验，保留全局硬件屏障 | 否 |
| 板端派发后SSH中断、进程退出或结果不明 | 待核验，检查原Run及收据 | 否；不能根据重连或帧计数重跑 |
| 重启时原Job仍RUNNING | 默认待核验；仅完整完成/恢复证据允许续交付 | 只续收，不能自动重放 |
| 硬件已完成，云端评测失败/未知 | 保留回放目录；明确评测失败或续收原云端执行 | 否 |
| 卡片/TXT发送失败 | 续交付原通知/附件 | 否 |

本次补充了恢复判断：即使`exists()`为假，只要锁路径仍是悬空符号链接，也不能判定安全释放。
