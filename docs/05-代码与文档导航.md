## 各类文件的性质

| 类别 | 是否权威 | 管理方式 |
|---|---|---|
| docs/当前文档 | 当前入口 | 修改能力必须同步流程、问题清单和验证边界 |
| skills/…/references | 详细设备手册 | 保留原路径/认证/迁移步骤，状态段落注明日期；链接回当前基线 |
| config参考、*.example.* | 模板 | 缺省关闭真实执行，不是完整生产配置 |
| workstation/systemd-reference | 单元参考 | 文件存在不等于现网已托管；切换须现场核验 |
| cloud/evaluator | 上游源码参考 | 不随文档整理修改指标；固定二进制/头文件依赖另取 |
| docs/archive | 历史资料 | 不作为当前安装命令来源 |
| Linux research/backups | 现场原始证据 | 保留业务数据和备份，不导出进Git |
| 未部署候选 | 非现网能力 | 仅保留现场可审查位置，不提供直接覆盖脚本；上线前重新合并 |

本轮不移动生产目录和固定依赖，原项目“预瞄悬架台架评测”保持只读。GitLab维护本统一入口，不把另项目代码、用户结果或整个旧项目混进来。

## 文档修改规则

需要更新现状时先改当前基线和问题清单，不继续追加互相覆盖的日期条款。设计讨论与候选单列，已部署变更必须附源码、测试、部署和真实验收范围；历史状态保持原日期。

源码静态检查见根tools/check_repository.py。它只验证语法、Markdown相对链接和明显禁止纳入的文件，不能验证生产配置、完整秘密扫描、物理设备或云端账号。
