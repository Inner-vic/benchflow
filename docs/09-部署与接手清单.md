常规迁移只更换Windows常驻电脑，复用原Linux、台架和飞书应用。源码维护、设备切换、真实任务验收分别进行；克隆仓库不等于部署完成。

## 接管前检查

1. 严格SSH登录ubuntu-workstation，可信核对主机公钥、账号lixiang、实际目录和解释器。
2. 只读检查所有项目硬件/后处理Job、准备、附件、解析、到点分析、归档，以及Runner队列/JSON锁。不能按PID消失、超时清锁或重跑。
3. 比较源码摘要及他人变更；把本次精确原文件、私有配置和一致性数据库快照备份到Linux。只改文档不重启。

```bash
cd /mnt/data/bench-eval/service/gateway
/home/lixiang/miniconda3/envs/tvg/bin/python -B -m bench_gateway.deployment --root /mnt/data/bench-eval/service/gateway status
systemctl --user show bench-feishu-gateway.service -p ActiveState -p SubState -p UnitFileState
/home/lixiang/bench-eval/bin/bench-eval queue
```

不要输出整个gateway.json、credentials或认证文件；不要为迁移停用其他项目正在执行的任务。

## Windows准备与切换

准备当前用户的Python3.11+、pythonw、Windows OpenSSH和已授权Codex CLI。补丁版CC Connect与原生desktop_gateway_adapter.exe没有进Git，须从受控现安装取得并按既有登记验证；普通上游CC不能直接替代菜单/附件补丁版。

从windows/config/gateway.example.json建立本机私有配置，角色ai-client。核对SSH别名、remote_project_root、remote_python、cc_project、连接代次及两项二进制绝对路径。不要把Linux参考配置覆盖到Windows。

单步工具为windows/tools/windows_client_setup.py、tools/register_windows_host.ps1和register_desktop_frontend.ps1；先阅读help/脚本再执行。新机Codex登录、SSH公钥登记和主机可信核验可能需一次人工操作，不复制旧私钥或浏览器资料。

先禁用旧连接端周期触发并正常排空，确认CC子进程结束和租约释放，再停旧解析端。新机先解析后连接，核对唯一入口及Linux识别新客户端。未知旧租约不能手工删除。计划任务按当前用户登录触发，不能承诺无人登录、睡眠或断电时在线。具体步骤见[Windows迁移](../skills/bench-gateway-operations/references/03-Windows迁移交接.md)。

## 认证、平台与云端

JFrog下载认证、Jenkins构建参数认证、GitLab只读源码Token、飞书Secret及原云端签名私钥留Linux受限私有目录。Windows通过受控SSH管道接收CC必要配置；迁Windows通常不需重做工作站平台登录。Jenkins与JFrog认证分开；M100原脚本参数与运维路径见[构建规则](11-M100官方构建与自动编译.md)。LPAI原主入口用官方SDK主授权申请临时STS，不依赖Windows浏览器Cookie。

PCM测试1另有专属账号/签名绑定及可选受限SSH转接；其私有配置、转接服务和完整外部部署不入Git。不能把其profile、公钥或账号与原主入口混用。主授权到期、2FA或启动审批可能需人工，Codex可引导验证，不能保证永久免登录。心跳仅代表接收器存活，不续期账号。见[认证手册](../skills/bench-gateway-operations/references/06-认证与授权.md)。

输入授权卷路径后，工作站SDK直接下载所选original至datasets/<源目录名>，同源已完成场景复用、扩范围补缺失，GT不下载；工作站路径也支持。评测用该任务的GT关联，禁止默认PCM/V151。工作站自动打包必要预测、签名上传专用输出卷，实例挂GT按完整场景匹配，TXT再续收工作站交飞书，用户不用填写回放结果路径。

实例挂载dataset-ga、chassis-ga和vc-chassis-bd-ga输出卷，精确路径见02。旧主入口策略、测试1专属f5f8…profile和本轮未安装b0a3…候选不得互换。接实例先查精确UID、挂载、公钥、程序/工具摘要、单接收器和新鲜profile心跳，最后再追加策略时间版本，旧Job保持冻结。见[云端手册](../skills/bench-gateway-operations/references/05-LPAI挂载与调用.md)。

## 验收与回退

先静态检查和相关离线单测，再验SSH、broker、唯一CC、本人菜单/材料卡和附件更新。真实台架任务必须用户点击确认，不伪造或重放回调。新版本、新场景及目标的实机验收另行记录。

切换失败先确认新连接端/解析端结束，再恢复旧入口。仅回退本次代码和配置，不恢复旧数据库覆盖新活动，不清锁、不重复推理。交接记录清楚哪些已验证、哪些待验证及外部依赖。
