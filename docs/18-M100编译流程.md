# M100.so 评测编译流程

## 编译目的

`liburoad_m100.so` 是 APP 运行时加载的 uroad 动态库。台架评测需要这份库具备相应的数据输出能力：以普通 APP 的配套源码和依赖为基础，开启 `WITH_EVAL_DUMP`，重新编译 M100.so，再与配套运行配置一起装配，供回放和评测使用。

普通 APP 保留原始身份。另行编译的评测 M100 必须单独记录来源、模式和装配关系，形成可追溯的评测材料。

## 流程与实现状态

| 阶段 | 职责 | 实现状态 |
| --- | --- | --- |
| Jenkins 发包 | 交付普通 APP、集成 Lockfile 和构建记录 | 当前 Bot 代码适配完成，待部署和真实发包验收 |
| 评测 M100 准备 | 从该 APP 还原源码与依赖，沿用原 `build.sh` 编译 ON 版动态库 | 已明确目标步骤，自动评测变体与材料装配接收仍待适配 |
| 现有自动 M100 编译 | 根据 APP 官方配置还原并编译配套动态库 | 既有实现保留 APP 官方 ON/OFF；普通 OFF APP 仍按 OFF 处理 |
| 台架回放与指标评测 | 装配材料、回放产生预测结果，再与匹配真值比较 | 既有任务按原确认和执行规则处理；普通 APP 加另编 ON M100 的目标链路尚未验收 |

本页下述步骤定义评测 M100 的目标流程。现有自动程序的运行规则见[M100 官方构建与自动编译](11-M100官方构建与自动编译.md)，两者的实现状态分别管理。

## 输入与版本来源

| 材料 | 来源与核对方式 |
| --- | --- |
| 普通 APP、构建链接和集成 Lockfile | 取自同一次成功构建，核对构建编号及文件摘要 |
| uroad 源码 | 从 Lockfile 中的 M100 精确配方修订反查固定提交，使用该提交的源码副本 |
| conan_shared、SDK、消息库 | 从本次 Jenkins 参数和集成锁交叉核对，形成构建基准与依赖清单 |
| 相机、雷达依赖及运行 SO | 开发依赖供编译使用，运行 SO 供接口和装配核验；均须与本次软件来源对应 |

用户提供构建卡片及台架材料。系统依据构建记录还原版本；构建记录缺失、依赖冲突或权限不足时，应指出具体缺项。分支名称和历史成功配置不能替代本次提交及依赖证明。

## 目标评测流程（待适配）

| 步骤 | 操作 | 应保留的结果 |
| --- | --- | --- |
| 1. 确认软件身份 | 核对 APP、构建编号与 Lockfile | 原 APP 摘要、构建链接及锁文件摘要 |
| 2. 还原编译输入 | 定位 M100 配方、源码提交及 SDK、消息库、传感器依赖 | 固定源码与依赖清单；任何额外调整须说明来源和原因 |
| 3. 准备隔离环境 | 在本人 Linux 工作站目录创建源码副本，使用已核验镜像及私有 Conan 环境 | 环境身份与构建目录，保留共享源码和其他任务环境 |
| 4. 开启评测编译 | 在本次私有构建配置中明确设置 `WITH_EVAL_DUMP=ON`，核对已有配方覆盖项 | 原 APP 模式、目标 ON 模式及配置差异 |
| 5. 运行原脚本 | 在配套容器内运行源码自带的 `build.sh`，安装依赖、编译并打包动态库 | 原脚本日志、实际生成的依赖锁及 M100.so |
| 6. 核验产物 | 检查有效编译模式为 ON，核对实际依赖、AArch64 架构、文件摘要及配套运行 SO 接口 | 与原 APP 绑定的编译收据；编译通过单独记录 |
| 7. 装配与回放 | 将评测 M100 与 APP、传感器 SO、YAML 组成材料，核验运行输出配置并取得材料确认 | 评测装配身份、台架回放结果及真实预测文件 |
| 8. 指标评测 | 将预测结果与本任务匹配真值交给评测程序 | 指标结果；回放成功和评测成功分别记录 |

原脚本的调用形式为：

```bash
./build.sh -t schu -o platform=schu -s -v conan_shared/<本次版本>@livc/release-schu
```

`<本次版本>` 取自本次 Jenkins 构建记录。`-v` 指定构建基准，ON 模式需在此前的私有构建配置中确定。脚本也可能编译缺失的开发依赖；原脚本产物位于 `install/lib/liburoad_m100.so`。

## 开关生效与结果判定

| 位置 | 含义与核验方式 |
| --- | --- |
| `CMakeLists.txt` 的 `option(WITH_EVAL_DUMP ... OFF)` | 声明默认值；需同时检查配方传入的值 |
| Conan 配方的 `self._cmake.definitions["WITH_EVAL_DUMP"]` | 可显式覆盖默认值；目标流程须使实际传入值为 ON |
| 构建生成的 `CMakeCache.txt` | 核验本次有效编译模式，作为产物证明的一部分 |
| YAML 的 `eval_dump.enable` 及分项配置 | 控制运行输出；还须检查实际预测文件是否产生 |

评测 M100 的基础源码与依赖需可追溯，宏控制的具体代码范围以该提交为准。编译成功说明动态库已生成；运行输出和指标结果还须通过回放及评测分别验证。

若 ON 编译缺少接口，先核对配套开发依赖；若实际模式仍为 OFF，检查配方覆盖及有效构建参数；若回放没有所需结果，检查运行配置、输出路径和执行收据。保留失败材料和日志，不自动猜版本、反复重编或重跑已完成台架任务。

## 当前接入边界与代码依据

现有自动编译会保留 APP 官方模式，并在 OFF 软件要求指标评测时提示不匹配。目标评测流程需要在原 `build.sh` 路径上补齐独立模式证明、评测 M100 来源记录及装配接收，相关代码和实机验收尚未完成。本页更新不改变现有程序或已确认任务。

- [输入还原](../workstation/gateway/bench_gateway/m100_auto_inputs.py)：关联配方、源码和依赖，读取官方模式。
- [编译协调](../workstation/gateway/bench_gateway/m100_build.py)：检查模式与任务目标，保存编译身份及状态。
- [远端容器执行](../workstation/gateway/bench_gateway/m100_build_remote.py)、[原脚本调用与产物核验](../workstation/gateway/vendor/build_uroad_eval.py)：执行原入口并核验有效配置、依赖锁和 SO。
- [台架材料适配](../workstation/gateway/bench_gateway/candidate_adapter.py)：核验运行配置与编译能力，形成装配和执行约束。
