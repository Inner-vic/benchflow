# 架构说明：契约、资源与证据

## 系统边界

核心编排层处理目标依赖、任务状态、资源占用和产物身份；适配层处理设备进程、传感器端点、文件布局与计算平台。前者承载可迁移的设计，后者必须针对环境重新验证。

Job 描述一次任务的输入、来源、目标、场景与提交者。Profile 描述环境能力与受控命令集。执行器对二者进行校验，再实施副作用。公开示例不是生产设备配置。

## 实现映射

| 设计职责 | 模块 | 不变量 |
| --- | --- | --- |
| 依赖规划 | `workflow_planner.py` | 来源与目标不能冲突；复用满足身份条件 |
| 持久协调 | `runner_state.py`、`queue_worker.py` | 任务身份固定；仅需要台架的任务占用锁 |
| 副作用控制 | `bench_transaction.py`、`direct_package_install.py` | 变更前记录基线；验收或恢复前不释放资源 |
| 节点复用 | `workflow_receipts.py` | 历史记录必须与当前输入输出相符 |
| 结果交付 | `prediction_transfer.py` | 不覆盖冲突产品；保留源产品与清单 |
| 评测尝试 | `evaluation_runner.py`、`parse_eval_report.py` | 新尝试独立保存；退出码不能替代覆盖门禁 |
| 人机协作 | 执行 Skill 与批次脚本 | 只补当前缺少的输入；工具约束不能由对话绕开 |

## 恢复依赖什么

任务状态说明流程走到哪里，节点收据说明什么工作已得到验证，产品身份说明当前结果是否仍与记录一致。三者相互补充，不能只凭某一个成功标记决定继续执行。

台架步骤失败时先恢复设备；产品已验证后，下游失败只影响上传、交付或评测。新的评测尝试记录新的输入与日志，旧失败证据保留。当前实现支持明确阶段边界上的恢复，不提供通用逐帧断点续跑。

## 信任边界

个人身份与认证会话在个人环境维护。工作站保存共享产品与逻辑任务归属；同一 Linux 账号下的逻辑隔离不等于操作系统级租户隔离。实际部署还需账户、文件权限及平台访问控制。

AI 输出通过任务协议和命令集进入执行器。Profile 本身仍需审查，因为命令集承载实际权限；将命令移到配置文件不会自动让它们安全。

## 接入另一类设备

1. 明确输入身份、目标与验收条件，保持任务协议语义。
2. 实现设备健康检查、基线捕获、候选激活、回放与恢复适配器。
3. 定义预测产品结构与必要输出，再接入传输和收据。
4. 适配真值与评测器，明确有效样本与覆盖规则。
5. 离线检查失败路径，用小场景实机验证恢复与交付；冻结基线后推广批次。

设备端口、服务命令、构建依赖和真值规则属于环境能力，不能只靠替换地址完成迁移。
