# Jenkins 发包

## 功能定位

Jenkins 发包用于将指定源码分支和组件版本构建为普通 APP，并交付软件包、依赖锁文件和构建记录。

该功能复用高鹏 Skill 的参数预填、构建确认、任务跟踪和结果交付流程，使用现有 `TRANSIT/XCU/SCM/CCU-ACORE-RELEASE-BUILD` 流水线。Skill 负责组织输入与核验参数，Jenkins 负责实际编译、集成、打包和上传。

## 输入配置

以下为当前代码适配的使用方式，线上入口须完成部署验收后启用。

在 Bot 中发送 **Jenkins 发包**，打开构建卡片并填写以下字段：

| 字段 | 填写要求 |
| --- | --- |
| 源码分支地址 | 提供本次 uroad GitLab 分支链接；校验时固定实际源码提交 |
| 软件版本 | 填写本次 `BASE_LINE`，格式为四位十六进制字符，可带 `SW` 前缀 |
| 构建类型 | 选择 `release` 或 `debug`，默认为 `release` |
| 组件版本配置 | 填写精确组件引用，每行一项，支持直接修改和追加 |

组件配置默认带出本人上次确认的内容；首次使用展示以下空版本模板：

```text
conan_shared/@livc/release-schu
uroad_m100/@livc/stable
dag_compiler/@livc/stable
```

三项版本均须补齐。新增组件沿用 `组件名/版本@用户/通道` 格式。历史配置作为编辑起点，仍须与本次分支重新核验；软件版本和分支按本次任务填写。软件 ID 按当前 AVM 约定固定为 `0111`。

用户提供分支、软件版本及组件选择；Skill 核验源码提交、依赖关系、匹配基线和最终 Jenkins 参数。`APP_VERSION` 提供组件版本，实际集成范围由原流水线的 `package.lst` 决定。缺项、版本冲突或来源不明确时，先完成核对再提交构建。校验通过说明输入与来源已核验，实际编译、接口兼容和台架运行仍须分别验证。

### 源码与组件的对应关系

分支链接用于确定目标源码，Jenkins 实际通过 `APP_VERSION` 中的组件配方获取代码。因此，所选 `uroad_m100` 的取码来源必须与本次确认的源码提交一致，不能仅凭版本名或分支名判断。没有匹配的已发布组件时，应先通过原组件 CI 准备对应版本，再核验发包参数。

执行需具备目标源码及制品库的读取权限、原 Jenkins Job 的构建权限。当前 Bot 使用已发布的普通版组件；缺少匹配版本时提示补齐，组件 CI 发布另行处理。账号凭据通过已有认证机制使用，不填写在卡片中。当前 Bot 复用工作站配置的 Jenkins 认证；飞书操作者与 Jenkins 实际发起账号分别记录，浏览器切换登录不会自动更换后台凭据。

## 执行流程

| 阶段 | 处理内容 |
| --- | --- |
| 配置校验 | 解析分支，核对 M100 配方的实际源码提交、普通版构建配置及配套依赖，生成最终参数 |
| 构建确认 | 展示源码提交、软件版本、构建类型、`APP_VERSION`、`LOCKED_LIBS` 及通知去向，由用户确认 |
| 构建执行 | 向原 Jenkins 流水线提交一次构建，按真实队列和构建编号跟踪状态 |
| 结果交付 | 核验构建产物与链接，返回构建结果，沿用原流水线的正式卡片通知 |

“校验构建配置”仅校验输入；通过后点击“确认发包”才提交构建。编辑后的参数须重新核验，打开卡片或执行校验不更新本人已确认配置。提交结果不明确时先查询原任务，避免重复构建。

## 交付结果

成功构建交付一份普通 LIVC APP、对应的集成 Lockfile、Jenkins 构建链接及下载校验信息。正式飞书卡片由原 Jenkins 通知机制发送，包含 APP、Lockfile 和构建链接；接收群及被提醒用户以原 Job 的通知配置和 Jenkins 实际发起账号为准，不按飞书操作者自动推定。

失败时返回实际构建状态、错误摘要和已生成产物，保留原构建编号用于排查。

## 台架衔接

用户转发构建结果卡，进入现有台架材料准备流程。依赖替换、M100 编译、运行配置核对和台架执行在该阶段单独处理，构建成功不自动启动台架任务。

台架评测的目标是根据该 APP 的源码和依赖，在工作站打开评测开关，使用原 `build.sh` 编译 ON 版 M100，再按原材料流程替换、回放和评测，详见[M100.so 编译流程](18-M100编译流程.md)。当前自动程序仍保持 APP 官方模式，这一评测编译及装配衔接尚待适配和验收；Jenkins 发包功能不修改 M100 或台架程序。

## 实现状态

当前 Bot 源码已适配本页流程，卡片、参数生成、确认、派发和结果交付使用同一份普通 APP 构建计划。新任务不再生成成对配方或启动组件发布 CI；历史已确认任务按原冻结计划恢复，未确认的旧参数须重新校验。

源码对应性检查在校验和首次提交前执行，构建完成后核验实际 Lockfile 的组件与配方修订。原 Jenkins 会重新解析组件，校验记录不替代实际构建结果。

代码已通过隔离回归，尚未部署或进行当前流程的真实发包验收。部署要求与验证范围见[部署与验证](19-Jenkins发包部署与验证.md)。生产状态以[部署基线](06-部署基线.md)为准。
