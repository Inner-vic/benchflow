## 三处设置的关系

| 位置 | 含义 | 本入口如何处理 |
|---|---|---|
| `uroad/CMakeLists.txt` 的 `option(WITH_EVAL_DUMP ... OFF)` | 声明预测落盘代码的编译选项；OFF 是源码默认值 | 保留原文件，不通过改默认值切换版本 |
| Conan 配方的 `self._cmake.definitions["WITH_EVAL_DUMP"]` | 向同一个 CMake 选项传参，不是另一个开关 | 使用所选 APP 精确配方中的布尔值；配方未显式设置时读取锁定源码的明确 CMake 默认值，并记录来源。动态、重复或有覆盖的参数不能猜测 |
| `common_param.yaml` 的 `eval_dump.enable` | 运行时是否启用落盘 | 检查本次软件和用户候选配置，不因执行目标暗中切换；冲突提示修正 |

源码开关为 ON 才具备对应编译能力；还需要运行配置开启落盘才能生成相应预测结果。是否继续执行指标评测是后续独立的任务目标。分项输出、`input_traj` 和 `sus_preview_timeline.csv` 仍须根据源码、分项配置和实际产物核对，不能据一个总开关保证齐全。

## 软件与任务组合

| 本次软件／配置 | 任务目标 | 行为 |
|---|---|---|
| 官方 ON、运行落盘 ON | 仅回放 | 保持 ON，回收预测结果；跳过指标评测 |
| 官方 ON、运行落盘 ON | 回放后评测 | 回收预测结果，随后按本任务真值关联进行评测 |
| OFF、运行落盘 OFF | 仅回放 | 保持 OFF，使用既有完成与服务恢复收据路径，交付日志和证据目录，不等待不存在的预测文件 |
| OFF 或运行落盘未开启 | 回放后评测 | 在材料／绑定阶段说明需要官方 ON 版本及配套配置；不自动把 OFF 编译成 ON |
| 编译为 OFF、运行配置却为 ON | 任一目标 | 提示软件与配置不一致，未提交台架 |

仅凭文件名包含 ON/OFF、旧成功记录或用户上传 SO 的名称，不能证明编译能力。成品 SO 没有编译来源元数据时仍做既有静态检查和本次启动预检，不伪造其宏取值证明。

## 缺少 M100 时的自动编译

1. 用户提供所选官方 LIVC APP、构建链接及配套材料；真实点击材料卡的“确认执行”。有明确提供且核验通过的 `liburoad_m100.so` 时使用成品，不再编译。
2. 工作站先完成 APP、相机／雷达 SO 及 YAML 前置检查。前置材料失败时编译尚未开始，不报成“编译失败”。
3. 工作站用独立的 Jenkins 只读认证读取构建链接。只接受与 APP 编号一致且已成功完成的构建：`APP_VERSION` 中的精确 `conan_shared/...@livc/release-schu` 用于 `-v`；SDK、function-message 从本次 `APP_VERSION`／`LOCKED_LIBS` 取值（不同构建中所在字段可能不同）。版本范围、重复冲突、缺项、无权限或历史记录已清理时停止，不套用旧参数。只保存白名单版本参数，不保存整个 Jenkins 响应。
4. 根据 APP 原始文件名下载集成 Lockfile，定位精确 `uroad_m100` Conan 配方修订及 40 位 Git 提交；与 Jenkins 的 SDK、消息库、已声明的相机／雷达开发包逐项交叉核对。原脚本使用 `liconan-dev-local`，官方开发版配方也从该仓库按精确修订读取。使用同版本源码中的本地 `conanfile.py`，按文档对齐 SDK、消息库；存在 Jenkins 明确指定且集成锁一致的相机／雷达开发包覆盖时同步保留，避免源码中的普通开发包盖过官方配套包。每项差异留存。
5. 读取精确官方配方／源码的 ON/OFF 参数，支持明确的布尔值及 `ON`／`OFF` 字符串。CMake 和原 `build.sh` 不修改；在私有配方中固化相同的官方宏值，不按任务目标翻转。调用原脚本：

   ```bash
   ./build.sh -t schu -o platform=schu -s -v conan_shared/<本次版本>@livc/release-schu
   ```

   原脚本负责安装公司 Conan 配置、获取基准锁、生成 `build/conan_shared.lock`，随后 install／build／package。不再用旧的三条离线 Conan 命令替代原入口；不额外传旧实现的 `-b release`。脚本只接受已审查的 SHA-256，发生变化先审查，不带认证执行未知脚本。
6. 使用固定镜像及独立源码副本、可写 Conan home，现有依赖包只读引用；不改共享缓存。JFrog、GitLab 凭据通过私有临时文件供容器启动器读取，不放 Docker 命令行或持久环境；原配方需要源码构建时向其子进程提供 GitLab 只读环境，日志脱敏。结束后停止本容器并删除临时凭据及 `.conan.db` 登录缓存。原脚本首次冷构建可能编译缺失的开发依赖，该路径编译上限 600 秒、整个材料准备上限 900 秒，旧路径仍为 300／600 秒；明确错误立即停止，不自动循环重编。
7. 保存原脚本实际生成的构建锁、CMake 有效 ON/OFF、日志和 SO。核对实际依赖引用、AArch64、摘要、本人归属及传感器接口，再绑定本次台架候选。编译成功不是实机通过。
8. 接口／锁不匹配时停止，要求手动编译并提交配套 M100，保留其余材料。连接中断、结果未知时先核对原构建记录，不自动启动第二次编译。

工作站目录沿用 `/mnt/data/bench-eval/users/<本人标识>/build-inputs/<APP摘要>/` 与 `builds/m100-<构建标识>/`。原脚本路径使用 `source-buildsh-v5`、`inputs-buildsh-v5.json`；旧离线 v2/v3 和本轮中间候选快照保留，不覆盖或冒充原脚本来源。换 APP 后不继承旧 M100；相机／雷达可沿用本人候选并重新核对。APP、传感器或来源改变需要重新准备；仅改变指标评测目标不改变官方构建模式。

Jenkins 认证位于 Linux `gateway/runtime/source-auth/team-m100-ci/jenkins.json`，按主机隔离、Fernet 加密和 0600 权限保存；不借用 JFrog 密码或浏览器 Cookie。管理员通过 `bench_gateway.m100_ci.configure` 和安全密码输入配置，验证登录成功才替换。只更换 Windows 入口时，该工作站认证不需迁移或重新登录。凭据和密钥不进 Git。
