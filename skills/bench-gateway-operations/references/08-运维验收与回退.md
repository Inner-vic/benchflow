## 分层验收，避免误判

1. Windows两个计划任务/连接状态正常。
2. Linux监督器、worker、broker和连接观察器就绪。
3. Windows受限模型真实解析往返通过，不能只看登录缓存或进程ready。
4. 飞书真实菜单、转发APP解析、SO/YAML保存及原卡更新正常；保存材料不执行。
5. 用户点击当前材料卡确认后，Preparation/Job仅登记一次，输入版本保持冻结。
6. 工作站到台架严格SSH检查成功；原Runner无未知执行/异常锁。
7. 经授权的真实小场景→正式范围→恢复/产物收据→目录交付通过。
8. 若评测，另核对云端最新profile心跳、正确GT、自动上传、收据/TXT及飞书附件交付。

后层不能用前层成功代替。迁移/打包不授权第7步，不代用户确认。新软件包、第二真实用户、新机重启和新数据集全量等未做的项不能因为旧包成功就标记通过。

## 故障对照

| 现象 | 优先检查 | 禁止的“修复” |
|---|---|---|
| 当前配置不出卡 | Windows CC租约/长连接、Linux receiver、真实菜单回调 | 另开竞争长连接；重放确认 |
| 自然语言超时 | Windows解析端、Codex登录/网络、AI broker分类 | 清空材料；无限大模型探索；将思考过程发飞书 |
| APP 401/403 | 工作站专用下载认证和JFrog路径权限 | 用浏览器已登录替代工作站认证；聊天索取密码 |
| 重试重复下载 | 本人download-sources、内容核验和版本URL | 跨用户取缓存；缓存损坏自动覆盖 |
| M100_RECIPE_MISMATCH | 本APP受控配方是否已上线；区分未配置与真正C++失败 | 默认套2737锁；把运行SO当开发头文件；随机换雷达版本 |
| YAML错误 | 明确目标、字段、类型、候选差异和回放协议冲突 | 猜字段或改原APP；材料不全仍编译 |
| 台架不可达 | 工作站路由/物理连接、SSH端口和认证分层 | 把所有错误归为网线；跳过主机校验 |
| 有锁但没明显进程 | 核对精确文件身份、原生任务和恢复收据 | 按PID消失/重启/超时自动清锁 |
| 正常其他任务占锁 | 同一Job留队，等待安全释放 | 直接报待核验；另起第二任务重复已完成帧 |
| 心跳过期 | 平台实例状态、接收端启动、profile、授权、对象存储分别查 | 自动判断登录失效；伪造心跳；重复提交评测 |
| GT缺失/歧义 | 当前evaluation_source、授权挂载及精确场景 | 默认V151；删指标/改阈值；把PARTIAL当全部成功 |
| 通知失败/TXT未到 | 只续通知/原报告，核对发送回执 | 重跑台架或重新计算来补消息 |

部署失败只回退本次代码和明确改过的静态配置，不回滚业务数据库或新用户活动。恢复原维护状态，核对会话、材料、确认和任务没有重置或重复派发。恢复不明继续待核验。打包或更新文档不自动开启真实调度、不启动云端、不清理历史任务。
