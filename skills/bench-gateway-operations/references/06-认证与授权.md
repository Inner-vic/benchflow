# 认证、账号与跨设备稳定性

> 当前流程、现场状态和问题以[2026-11-05文档入口](../../../docs/README.md)为准。本页保留设备配置细节；注明11月3日的观察和ZIP交付范围属于历史快照。

## 各种认证不是同一件事

| 对象 | 认证发生在哪里 | 存储/刷新与迁移处理 |
|---|---|---|
| Windows→Linux SSH | 新Windows用户的SSH客户端 | 新机生成或复用获授权身份，登记公钥；私钥留新机用户目录；核对工作站主机公钥 |
| Codex模型访问 | Windows当前用户的Codex CLI | 使用该用户官方登录和自身缓存；不能复制旧`.codex`或假定登录永久有效 |
| 飞书机器人 | Windows CC通过长连接；凭据权威在Linux | Linux `runtime/credentials.json`受权限保护；App Secret经受控SSH管道注入进程环境，不进聊天或Windows配置 |
| 飞书用户身份/确认 | Linux程序校验原消息/私聊/回调签名 | 不靠模型判断身份；可用范围是准入，目录/任务归属还需逐次检查 |
| JFrog下载 | Linux对批准HTTPS域名发送Basic认证 | 专用团队账号加密记录在`runtime/download-auth/team-download-v1/`；Fernet密钥受私有权限保护；凭据轮换才需更新 |
| GitLab源码读取 | Linux本APP自动源码接入工具 | 只读Token留私有source-auth；11月5日已部署并验证2880冷发现/编译，不在代码或命令参数写Token |
| Jenkins构建参数 | Linux按APP编号读取固定Release构建API | 独立认证加密存于`runtime/source-auth/team-m100-ci/jenkins.json`，仅保存白名单版本参数；不混用JFrog密码或保存全量CI响应。原M100脚本的GitLab环境仅供构建子进程，日志脱敏、结束删除临时凭据和Conan登录缓存 |
| LPAI主认证 | Linux `/usr/bin/python3`中的官方asset SDK | SDK配置位于`/home/lixiang/.lpai/conf.json`；由公司平台授权，不能按Windows浏览器Cookie推断状态 |
| LPAI对象存储STS | 工作站每次通过asset卷接口申请 | 内存/受控stdin传递，只读下载与输出上传分开；不写入数据计划或交接包 |
| 云端请求签名 | Linux固定签名工具；云端仅公钥验签 | 私钥只在Linux受限runtime目录；新Windows不需要复制；公钥不是JFrog或LPAI登录凭据 |
| 工作站→台架 SSH | 原Runner的固定SSH配置 | 主机身份与无密码登录是两回事；主机公钥变化须核验，不跳过StrictHostKeyChecking |

“配置页在本机填写”和“下载发生在本机”不是一回事。当前APP实际由工作站下载，LPAI数据实际由工作站直传对象存储；Windows仅控制、解析和连接。JFrog不是在工作站打开网页登录下载，也不是必须每次扫码。

## JFrog专用账号

团队凭据只授予下载能力，不授予跨用户软件复用。当前加载顺序优先团队下载认证，缺时按本人认证处理。候选账号保存、工作站读取少量真实artifact验证、验证成功后激活，是三个步骤；“保存成功”不等于已启用。

密码不要发聊天或置于URL。需要配置时由Codex引导进入现有安全填写入口；Linux受限配置可通过经审查的loopback/SSH隧道完成。不要套用旧Windows DPAPI文件去Linux；也不能只复制Fernet密文而丢掉原受控密钥。迁移Windows时业务认证仍留原Linux，通常无需重配。

401/403区分账号失效、来源权限及浏览器已登录但下载请求未带认证；不连续暴力重试，不把401说成文件不存在。

## LPAI稳定性边界

短期STS与主SDK认证有不同有效期。代码不会把STS长期写死，S3传输通过官方授权接口申请；但这不保证主JWT/授权被撤销、到期或公司安全策略变化时无需重新授权。本次没有依据可承诺某个固定TTL或永久免登录。

实例心跳不续期账号。实例停止、接收端未加载、profile不一致、SDK授权失效、对象存储网络失败必须分别诊断；不能看到心跳过期就让用户重复登录。

当前专用实例/输出前缀仍关联原维护者命名。希望以后使用统一公共账号，应使用组织批准的服务身份并授予输入卷读取、专用输出卷写入及实例操作权限；团队可见不是账号凭据共享。更换LPAI身份不能只迁移一个浏览器profile；先用该身份验证卷访问和固定接收端，再切换配置。

## 哪些必须人工一次性处理

新机账号登录、SSH公钥登记/可信主机核对、飞书应用权限或发布、平台额外审批/二次验证、被撤销或到期的公司授权，可能需要用户或管理员操作。Codex可准备可审查配置、定位入口和验证结果，不能绕过平台审批，也不能凭空自动登录任何账号。

不要把“所有账号密码交给Agent保存”作为方案。只配置本链路必需能力；不需要Windows密码、个人邮箱密码或台架私钥。交接包只含非敏感配置和路径说明，不含主认证、Cookie、App Secret、JWT、Token、私钥或Fernet密钥。
