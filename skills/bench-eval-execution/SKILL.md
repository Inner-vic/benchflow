# 台架评测执行：个人助手与确定性 Runner 的边界

此 Skill 是公开参考；示例地址、账号、产品身份与场景均已脱敏，不能作为生产配置。工作站 Runner 源码与设计见仓库 `automation/` 和 `docs/workstation-runner.md`。

## 1. 先明确来源与目标

任务可能要求新预测、已有预测的交付，或已有预测的评测。只补当前阶段真正缺少的输入：本次 APP、库、配置、数据身份、场景、端点与所需产品。凭据不进入 Job、Profile、日志和收据。

新执行使用新不可变 Run ID。失败和成功 run 都保留原身份。已有产品必须同时满足生产收据、当前清单和内容身份匹配，才能作为来源。

## 2. 分层执行

个人助手解释意图并组织任务。工作站 Runner 校验 Job/Profile，解析依赖，保存任务状态，管理队列与台架锁。台架产生预测，工作站保存权威产品，个人计算环境执行可选评测。

Job 只选择受控命令集，不携带任意 shell、command 或 argv。只有真正需要台架的任务取得独占锁。逻辑提交人归属不替代系统账户和文件权限。

## 3. 输入组合变化时建立基线

软件、动态库、配置、数据内容或回放端点变化时，不直接复用旧快速入口。完成环境适配和容量检查，用小场景验证预测生产、服务恢复与交付，再冻结输入身份并确认批次规划兼容。

端点数字变化不意味着库、驱动和健康检查已经兼容。

## 4. 将回灌视为事务

`precheck → capture_baseline → stop_active → start_candidate → health_candidate → replay → restore → verify_restore`

候选回灌成功或失败后均需核验正式服务恢复。正式安装更新使用独立验收条件。服务恢复不等于软件回滚。

恢复失败时保留台架锁、基线与日志，交由负责人处理。无法证明设备安全时，不提交后续回灌。

## 5. 产品与下游恢复

批末收集工作站产品，核对必需预测类型、逐文件清单、清单哈希与产品身份。需要团队交付时生成场景索引。

上传或评测失败保留已验证工作站产品，只处理对应阶段。仅补交付的恢复入口不能用于掩盖回灌失败或恢复失败。

每次评测尝试保存独立配置、日志和报告；失败重试创建新尝试，不覆盖旧证据。

## 6. 成功的含义

过程完成、产品一致、评测有效与算法达标分别判断。退出码为零不能证明真值匹配或任务覆盖。某任务无有效样本时明确报告缺口；没有阈值时报告指标，不自行宣称达标。
