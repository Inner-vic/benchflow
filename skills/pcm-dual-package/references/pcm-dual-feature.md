# PCM 双版本构建（独立功能）

当前功能分为两个独立阶段：双版本构建交付OFF/ON APP和两张结果卡；用户手动选择并转发其中一张卡片，才作为既有台架评测的软件输入。没有自动关联台架任务、自动迁移材料或发包后自动执行台架；后续整合不属于本次实现。下文关于软件来源追溯及不同装配的规则，不代表已经部署了跨阶段自动衔接。


本入口明确要求同一源码的两份 APP：普通版 OFF、评测版 ON。内部绑定 `feature=pcm_dual_app`、`delivery=app_pair`、`compile_modes/requested_app_modes=[OFF,ON]`、`app_count=2`。不改变原台架评测入口的一份 APP 加配套 SO 方式，不创建台架任务。

## 初始卡片

标题“PCM 双版本构建”，副标题“基于同一源码，生成普通版与评测版 APP”。输入源码分支地址、本次软件版本、构建类型和组件版本配置。软件版本新任务留空、不继承历史值；构建类型支持release/debug，初始为release。用户已明确全部任务为AVM，软件ID后台固定0111，卡片不再收该项。组件区是三行原生多行框，必填conan_shared、uroad_m100、dag_compiler三个精确引用，其他组件可在末尾追加。底部显示“构建产物：普通版 OFF · 评测版 ON”，唯一按钮“校验构建配置”。不出现数据集、SO附件、回放方式、执行目标或台架确认按钮。

软件版本对应 `BASE_LINE`，按现有构建规则收4位十六进制字符，可输入SW前缀。2026-11-12直接读取原Jenkins说明：SOFTWARE_BRANCH是软件ID，0111为自研EMB、0112为Bosch共研；不是Jenkins构建号，也不按发包次数递增。按用户后续明确的AVM范围固定0111，旧表单或CLI提供其他ID时拒绝，不改变已冻结旧任务。产品配置ULTRA/MAX由所选且已核验的基线确定；仅修改包名不能改变产品配置。

源代码在同一交接仓库的 `workstation/gateway/bench_gateway/pcm_dual_build.py`。`render_card` 只有接收与本人草稿一致的宿主回调绑定才启用校验按钮；默认是禁用的预览。不另开飞书长连接，不挪用原“当前配置”菜单。

首次没有本人确认记录时，后台组件值为空，卡片展示可编辑的三行空模板：`conan_shared/<版本>@livc/release-schu`、`uroad_m100/<版本>@livc/stable`、`dag_compiler/<版本>@livc/stable`。三项都必须填写精确版本；缺项或保留占位符会明确提示，不能自动套用历史版本。模板通道按用户要求展示，实际填写的引用仍须核验真实配方。其他组件由用户追加；自动解析的传递依赖保存在校验报告，不自动扩展编辑框。后续仅回填本人上次**确认**的有效配置，旧默认缺少必选项时仍须补齐。打开卡片、编辑、校验成功/失败都不能覆盖确认记忆。当前未结束草稿优先保留；确认后的新草稿回填组件，源码分支重新填写。

`uroad_m100`输入作为本次M100配方/版本基准，核验精确修订、配方摘要，并与本次源码Commit一同保存在报告。未来准备OFF/ON变体须据这些冻结输入生成各自引用，不能将基准旧SO作为本次已编译产物。该引用单独保存为m100_recipe_ref，不塞入公共APP_VERSION造成与变体重复；校验阶段仅生成隔离变体配方和参数快照，不发布、不编译；真实确认后才执行。重复组件、范围版本、不完整引用或超出原生1000字符限制会明确提示，不截断或静默取最后一行。

## 校验与记忆

校验通过只表示输入、分支 Commit、基线、组件配方来源及参数归类已核对，**不是**编译、接口/ABI、APP 发包或台架通过。

- 公共配置中的修改传给只读发现器参与匹配；源码声明不兼容时明确报告，不忽略用户修改或自动还原旧版本。附加组件也需要真实配方校验。
- 用基线锁钉住 recipe 修订，并核对远端 conanfile SHA。无锁定修订时只接受唯一来源，不猜最新修订；有歧义则补充核对。
- `begin_validation` 在独立数据库冻结本人会话、草稿版本、nonce、输入摘要和 attempt。同一旧卡重复事件不重复校验；过期结果不能覆盖新输入。
- `run_validation`运行注入的只读解析/配方读取器，并可生成最终确认快照，不做远端写入。异常在原卡反馈、保留内容，不保存默认、不重试构建。
- 后续真实参数确认在独立数据库事务内冻结任务、消费事件并更新本人默认；仅校验不更新默认。独立worker才会发布配方并提交Jenkins，不能把“校验”当成“确认构建”。

工作站独立状态文件为 `<state_root>/pcm-dual-build.sqlite3`，保存草稿、本人确认默认、卡片定位及回调幂等记录。`live_drafts` 限制在 Linux `/mnt/data/bench-eval` 下；不迁移原 gateway.sqlite3，不在原库创建构建任务。Windows只存程序和静态文档。

## 独立只读入口

在完整交接仓库内执行，复用已有网关加密认证，不把凭据写入配置文本：

```sh
python <skill>/scripts/pcm_dual_config.py \
  --gateway-root <现有网关目录> --state-root <本功能工作站状态目录> \
  --owner <已登记请求人> --session <本人会话> \
  --branch-url <本次GitLab分支链接> \
  --software-version <本次软件版本> \
  --build-variant release \
  --card-output <新的工作站卡片JSON路径>
```

可选 `--components-file` 读取工作站版本配置文本；不指定时仅载入本人的已确认配置。`--baseline-build` 是基线歧义时的高级补充，不在初始简洁卡常驻。CLI 没有确认、编译、发包或台架命令。

## 执行链路加固（2026-11-12）

已部署独立功能的最小修复，不改共享派发器：

- 远端配置查询使用单轮90秒预算，连接/读取单次等待最多10秒，分段读取时检查预算。达到预算停止后续请求，不能理解为网络调用精确在90秒强杀；正在等待的单次读取可能延迟至其超时返回。同轮相同URL复用内存响应，仍按当前读取上限检查；不跨轮缓存分支Commit或认证。
- 卡片进度发送失败时不静默开始远端校验；输入保留并说明尚未开始。校验后结果发送失败保留实际结果，重复同一事件只续交付，不再次校验。
- 基线选择失效、旧版本等输入拒绝保留具体原因，不再统一掩盖成“卡片更新未完成”。认证401/403、资源404、网络不可达及查询超时分别反馈，错误正文、凭据与原始认证URL不放进卡片。
