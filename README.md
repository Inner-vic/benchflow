# BenchFlow · 台架回放与评测

通过飞书材料卡确认软件和数据，由工作站组织构建、共享台架回放及结果交付。项目保留输入确认、用户资产隔离、硬件排队、执行记录和失败恢复的实现。

实际部署由 Windows 消息接入端、Linux 工作站、专用台架和 LPAI 数据/评测环境协作完成。公开仓库提供源码与配置参考，外部工具、硬件及平台权限需自行准备。

## 主要功能

| 功能 | 输入 | 交付 |
| --- | --- | --- |
| PCM 双版本构建 | 源码分支、软件版本和组件引用，经用户确认 | OFF/ON 两个 APP、各自 Lockfile、构建链接和结果卡 |
| 台架回放与评测 | 已有 APP、配套 SO、数据路径和可选 YAML，经材料卡确认 | 工作站回放结果目录；选择评测时交付评测 TXT |

两项功能共用 Bot，各自维护确认和任务状态。当前由用户手动选择并转发一张构建结果卡作为台架输入；构建完成不会自动派发台架任务。

台架材料确认后，工作站准备并冻结输入，经统一 FIFO 和 Runner 锁操作共享硬件，再恢复服务并交付结果。下游评测或通知失败只从对应阶段恢复，避免重复回放。

## 获取源码与本地检查

源码检查使用 Python 3.12，不需要连接台架：

```powershell
git clone https://github.com/Inner-vic/benchflow.git
cd benchflow
python -B tools/check_repository.py
python -B -m unittest discover -s tools/tests -q
```

这些命令检查源码边界、语法、文档链接和发布规则，不注册服务、不提交构建或台架任务。GitHub 的 [Source checks](.github/workflows/source-checks.yml) 执行源码及仓库检查，测试范围见[发布说明](PUBLICATION.md)。

## 部署前需要准备

- Windows 端：Python、CC Connect、Codex 和工作站 SSH 接入。
- Linux 工作站：业务网关、独立状态目录、Runner 及已核验的台架适配工具。
- 构建环境：对应的 Jenkins、制品源、Docker/Conan 环境与组件权限。
- 数据与评测环境：授权数据、GT、平台客户端和匹配版本的评测器。

`config/` 和设备配置样例不能直接覆盖实际部署。先阅读[部署说明](docs/09-部署与接手清单.md)，按自己的环境核对组件、身份及路径；原生二进制、APP/SO、业务库、数据和签名私钥均不在公开源码中。

## 源码结构

| 路径 | 内容 |
| --- | --- |
| `windows/` | 消息连接、受限解析及本机配置工具 |
| `workstation/gateway/` | 材料、构建、确认、队列与交付 |
| `workstation/runner-reference/` | 台架 Runner 和扩展参考源码 |
| `cloud/` | 数据与云端评测接收端相关源码 |
| `skills/` | 构建、执行及运维入口和设备手册 |
| `modules/` | 早期独立输入/计划模块，保留兼容调用 |
| `tools/`、`docs/` | 仓库检查、设计与维护说明 |
