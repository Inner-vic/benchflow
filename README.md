# 台架评测统一入口

源码仓库：[Inner-vic/benchflow](https://github.com/Inner-vic/benchflow)。先读[部署说明](docs/09-部署与接手清单.md)、[源项目历史基线](docs/06-部署基线.md)及[收录范围](docs/10-仓库收录与来源.md)。本库维护材料确认、软件构建、台架回放及评测源码；部署配置需要按自己的环境准备。

飞书私聊收集APP链接、SO/YAML和数据路径，用户在材料卡确认后，由Linux工作站准备材料、串行操作台架，交付回放目录或云端评测TXT。Windows运行CC Connect和受限Codex解析，Linux保存业务状态及文件。其他项目共用Bot时业务记录独立，板端必须统一FIFO；不属于本项目的评测链路不合并。

## 两个功能，一套仓库

本仓库维护两项独立能力，共用飞书 Bot，但各自确认、记录和执行：

| 功能 | 输入与确认 | 交付 |
|---|---|---|
| PCM 双版本构建 | 源码分支、软件版本、组件引用；校验后确认最终构建参数 | 普通版 OFF、评测版 ON 两个 APP，各自的 Lockfile、构建链接及结果卡 |
| 台架回放与评测 | 已有 APP、配套 SO、数据集路径及可选 YAML；确认台架材料 | 工作站回放结果目录，按目标交付评测 TXT |

当前衔接：用户选择并转发一张构建结果卡 → 台架材料卡接收软件来源 → 补齐材料 → 确认执行。构建成功不会自动创建或派发台架任务，构建确认不能代替台架确认。

后续计划是让用户从构建结果选择产物，自动带入台架材料卡；仍保留材料核对和台架执行确认。该自动衔接尚未实现，不能作为当前功能使用。

当前 Bot 构建使用 `workstation/gateway/bench_gateway/pcm_*`、独立软件状态库和 worker；详细说明见[双版本构建](docs/16-双版本构建确认与派发.md)。`modules/jenkins-input-card/` 保留早期离线输入/计划模块，兼容旧调用，不是线上 Bot 的第二套执行器。[旧双包交付](docs/13-Jenkins双包交付.md)中的身份清单和导出能力继续保留。

仓库合并不等于生产发布。运行目录、认证、业务数据库和任务保持独立；生产更新须另行备份、核验和部署。

## 边界

凭据、业务SQLite、APP/SO、数据集、预测、报告和现场审计原件留运行环境。补丁CC Connect、原生适配器、评测器二进制及Docker/Conan环境仍须按既有部署取得并核对摘要；克隆仓库不等于可从零自动重建四设备环境。

真实执行要求有效本人卡片确认；正常资源忙继续排队，未知结果待核验。通知、材料修复或评测失败不构成重跑台架的依据。

11月6日已恢复遵从所选APP官方ON/OFF，并接通Jenkins版本参数到原`build.sh`的M100自动编译，不按任务目标翻转宏或运行配置；缺M100时按本APP尝试，见[M100构建规则与真实纯编译证据](docs/11-M100官方构建与自动编译.md)。2950官方ON原脚本构建通过，未做新包实机回放。PCM测试1专属云端策略与原主入口旧策略仍不能混用，见[当前基线](docs/06-部署基线.md)。

静态检查运行 `python tools/check_repository.py`，规则自测运行 `python -m unittest discover -s tools/tests -q`。Linux定向测试见运维文档；测试通过不代表新包、物理台架、新电脑重启或云端实例均已验收。
